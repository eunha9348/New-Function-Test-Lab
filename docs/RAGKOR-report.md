# RAGKOR 분석 보고

> 웹 보고서: https://claude.ai/code/artifact/843a8edb-fd1d-413f-9b21-4c561e3f3ff7

## 한 줄 요약

한국어 문서에서 "모델이 말한 것이 원문에 실제로 있는가"를 판정하는 **규칙 기반 어휘 자원 + 자모 유사도 매처**.
표면형 10,000건 / 의미 클러스터 72개 / 시드 825개(사람 작성) / 사전 생성 0.05초 / 외부 의존성 없음.

**신경망을 훈련한 모델이 아닙니다.** GPU도 코퍼스 라이선스도 쓰지 않았고, 모든 항목이
어느 규칙에서 나왔는지 역추적됩니다(`origin`). 틀린 항목은 그 규칙만 고치면 되고 재학습이 없습니다.

## 왜 만들었나

기술제안서 PDF 실행 로그에서 세 줄이 이상했습니다.

```
[검증] 기계 검증기 8건 → 10건 → 13건 발견      ← 재작업할수록 늘어남
[감독] revise — 충실도 50점 → 30점 → 50점
소요 356.1초 · 추정 비용 $0.7653
```

감독이 환각으로 찍은 항목은 전부 원문에 실재했습니다. 감독이 지운 것은 환각이 아니라
**멀쩡한 성과 기술**이었습니다.

## 무엇이 문제였나

기존 검증기는 `정규화(인용) in 정규화(원문)` — 부분 문자열 포함만 봤습니다.
구두점 제거 목록에 `…`가 빠져 있었고, 모델이 긴 인용을 말줄임표로 자르는 순간 전부 환각이 됐습니다.

```
원문 · 연금 질의는 …다르다. 1. 틀린 답이 금전적 손해로 직결된다
인용 · 연금 질의는 …다르다. 1. 틀린 답이 금전적 손해로 직결된다…
기존 판정: 환각(blocker)   RAGKOR 판정: 근거 있음 · 일치도 97%
```

두 번째 문제: "근거 확보율 **22.8%p** 향상"을 환각으로 판정했습니다. 원문에 `32.9% → 55.7%`가
있으므로 22.8은 모델이 **옳게 계산한 값**입니다. 원문 문자열에 없다는 이유로 정확한 성과가 지워졌습니다.

이 오탐이 감독 프롬프트에 "기계 검증기 결과"로 들어가 재작업을 유발했고,
추출기는 지적을 피하려 멀쩡한 내용까지 빼면서 **매 라운드 결과가 나빠졌습니다.**

## 한계

- **의미가 아니라 표기를 봅니다.** 원문 문장을 그대로 가져와 맥락만 틀리게 붙인 경우는 통과합니다.
  벤치마크가 이 유형을 별도로 측정해 출력합니다(`[4] 알려진 미탐 유형`) — '한계' 섹션의 문장을
  '성과' 근거로 붙이면 `grounded (1.0)` 로 통과합니다. 의미 수준 검수는 감독 에이전트의 몫입니다.
- **사전은 도메인에 묶여 있습니다.** 시드는 경험 기록 도메인에 맞춰 썼습니다.
  다른 도메인은 시드 교체가 필요하지만, 재학습이 없어 교체 비용은 파일 하나입니다.
- **파생 수치는 단순 연산까지.** 차·합·비율·증감율만 확인하고 그 이상은 `unknown`으로 넘깁니다.
- **임계값은 이 평가셋 기준.** 0.85/0.55는 186건에서 고른 값이고 `ground.py` 한 곳에 있습니다.

## v3 — 검증된 부품으로 교체 + 필드 감사관 (2026-10)

RAGKOR에서 사람이 손으로 만든 부분 중 약한 곳을 공개 라이브러리로 바꾸고,
"각 칸에 맞는 정보가 들어갔는가"를 보는 최종 감사 단계를 추가했습니다. 모두 LLM 호출 없이 도는
부품이고, 새로 추가된 LLM 호출은 필드 감사관 1회뿐입니다.

| 부품 | 바꾼 것 | 결과 |
|---|---|---|
| 조사·어미 떼기 | 접미 목록 → **Kiwi** 형태소 분석 (`kiwi-nlp` WASM / `kiwipiepy`) | 활용형 40쌍 중 같은 원형: 규칙 15 → **39**. 굴절 사전 4,200건 중 3,949건(94%)을 사전 없이 재현 |
| 인용 위치 | 없음 → **RapidFuzz `partial_ratio_alignment`** 방식 | 근거 있는 인용 138/138 정렬. TS 구현이 rapidfuzz 점수와 일치(0.5 이상 구간 오차 0.02 이내, 223건) |
| 수치 3단 판정 | 유지. 단, 파생값은 원문에서 **200자 안에 함께 있는 두 수**로만, 비율(×100)은 값이 %일 때만 | '2'와 '5'로 '150', '2'와 '24'로 '1,200'이 우연히 '파생값'으로 통과하던 문제 해결. 기존 9/9 유지 |
| 맥락 검사 | 없음 → 섹션·문장 단서어 + **gemini-embedding-001** | 알려진 미탐 유형(한계 문장을 성과 근거로) 적발. 키가 없으면 단서어만으로 동작 |
| 오타 복원 | 정규화형으로만 자모 유사도 → 표면형도 함께 질의 | held-out 0.939 → **0.980** |

Kiwi를 켜면 사전 대표형('집중투입하다', '주도했다')과 Kiwi 원형('집중투입', '주도')이 어긋나는
문제가 있었습니다. 대표형을 Kiwi 원형으로 다시 색인해 한 대표형으로 모으도록 고쳤고,
규칙 모드는 예전과 똑같이 동작합니다(Python·TS 테스트 모두 그대로 통과).

### 필드 감사관 (`src/agents/auditor.ts`)

- **필드 계약**(`src/schema/contracts.ts`): 모든 칸에 역할 13종 중 하나를 붙이고 "넣을 것/넣지 말 것"을 정의.
  배분·감독 프롬프트에도 같은 계약이 들어갑니다.
- **기계 사전 감사**: 칸마다 근거 위치·일치도, 수치, 맥락, 같은 서술 문장의 중복 배치를 확인.
- **LLM 1회**: 칸마다 correct / wrong_field / distorted / incomplete / unsupported / fill.
- **관문**: 수정은 근거 인용이 원문과 정렬(≥0.85)되고 수치가 원문값·파생값일 때만 적용.
  적용 후 새 문제가 생기면 그 수정만 되돌림. 재작업 루프 없음.

오류 주입 평가(인턴 보고서 예제, `test/auditor.test.ts`)

| | 결과 |
|---|---|
| 정답 결과에서 잘못 찍은 칸 | **0** |
| 기계로 잡아야 할 오류 6종 | **6/6** (이슈 문장→성과, 행동만 있는 성과, 팀 주어, 원문에 없는 수치, 지어낸 근거, 성과 중복) |
| 의미 판단이 필요한 오류 2종 | 기계 0/2 → LLM 감사관 몫 (퇴사 사유→배운 점, 맡음→주도) |
| 감사관 수정 관문 | 지어낸 근거·원문에 없는 수치·채워진 칸 덮어쓰기·근거 단단한 칸 지우기를 모두 거부 |

LLM 감사관의 실제 정확도는 아직 재지 못했습니다(이 환경에 API 키가 없음). 실제 문서로
`npm run organize`를 돌려 `audit.summary`를 모으는 것이 다음 할 일입니다.
